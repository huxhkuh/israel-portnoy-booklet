# הרשמה לעדכונים מישראל — Google Apps Script ו־Google Sheets

הגיליון הקיים משמש להתחלת רשימת התפוצה של ישראל. הטופס אוסף **כתובת מייל חובה, שם אופציונלי והסכמה מפורשת לקבלת עדכונים**. ההרשמה אינה בקשה לשיחת חזרה, ואינה תנאי לקריאת החוברת או להורדתה.

הפתרון שומר הרשמות בלבד. אין בו כרגע שליחת עדכונים, סדרות דיוור, הודעות ברוכים הבאים או התראות אוטומטיות. `subscribeUpdates` אינו שולח מייל; חיבור כלי לשליחת קמפיינים הוא שלב נפרד.

האתר נשאר סטטי ב־GitHub Pages. הטופס מוגש מתוך Apps Script ומשתמש ב־`google.script.run`. הודעת הצלחה מופיעה רק אחרי שהשרת כתב את ההרשמה וקרא בחזרה את מזהה הבקשה והחתימה שלה. אין שימוש ב־`no-cors` ואין שירות ביניים בתשלום.

## הגיליון והרשומות

נעשה שימוש **באותו גיליון ובאותה לשונית קיימת**, לפי `SPREADSHEET_ID` ו־`SHEET_NAME`. אין ליצור רשימה נוספת. השם `פניות` נשמר כברירת מחדל לשם הלשונית, אך התוכן שלה הוא רשימת נרשמים לעדכונים.

| עמודה | תוכן |
| --- | --- |
| A | תאריך ושעת ההרשמה, לפי שעון ישראל |
| B | שם מלא — אופציונלי |
| C | אימייל — חובה, נשמר באותיות קטנות |
| D | מקור ההרשמה: `עמוד החוברת` או `באנר יציאה` |
| E | סטטוס הרשמה: `רשום` או `הוסר` |
| F | נוסח ההסכמה שהוצג |
| G | גרסת ההסכמה, כרגע `updates-v1` |
| H | `_request_id` — מזהה בקשה טכני |
| I | `_payload_hash` — חתימת הנתונים הטכנית |

העמודות H:I מוסתרות, אך אינן סוד בפני מי שיש לו גישה לגיליון. המסנן כולל את A:I; יש למיין דרכו, כדי שהמזהים וההסכמה יישארו צמודים לאותה הרשמה. שורת הכותרת קפואה ומודגשת, והטבלה מוצגת ב־RTL.

נוסח ההסכמה הנוכחי נשמר בשרת ומועבר לטופס להצגה:

> אני מסכים/ה לקבל במייל עדכונים ותוכן מישראל פורטנוי, ולשמירת הפרטים לצורך זה. אפשר לבקש הסרה בכל עת במייל לישראל.

## התקנה או עדכון של הפרויקט הקיים

1. פתחו את הגיליון הפרטי שהוכן לאתר ואת פרויקט Apps Script הקיים. אין לפרסם את הגיליון או לפתוח אותו לכל מי שיש לו קישור.
2. בעורך החליפו את תוכן קובץ הסקריפט בתוכן `Code.gs`, ואת תוכן קובץ ה־HTML בשם `Form` בתוכן `Form.html`. `Form.html` כולל עיצוב וקוד לקוח. אין להוסיף את הטופס כקובץ HTML רגיל ל־GitHub Pages.
3. ב־**Project Settings** הפעילו את הצגת `appsscript.json` בעורך, אם הוא אינו מוצג. השתמשו במניפסט המצורף: V8 ושעון `Asia/Jerusalem`. במניפסט קיימת גם הרשאת `script.send_mail` עבור קוד הפניות הישן; זרימת ההרשמה החדשה אינה משתמשת בה ואינה שולחת מייל.
4. ב־**Project Settings → Script Properties** הגדירו ושמרו:

   | הגדרה | ערך |
   | --- | --- |
   | `SPREADSHEET_ID` | המזהה של הגיליון הקיים והפרטי |
   | `SHEET_NAME` | `פניות` — שם הלשונית הקיימת |
   | `SITE_URL` | `https://huxhkuh.github.io/israel-portnoy-booklet/` |

   `NOTIFICATION_EMAIL` אינו נדרש להרשמה לעדכונים. אם הוא נשאר מההתקנה הישנה, הוא אינו מפעיל התראות ב־`subscribeUpdates`. מזהה הגיליון והגדרות השרת אינם נכנסים לקוד הדפדפן.
5. הכינו את הלשונית באמצעות `setupUpdates_`. אם הפונקציה הפרטית אינה מופיעה ברשימת ההרצה, הוסיפו זמנית בסוף `Code.gs`:

   ```js
   function initializeUpdatesFromEditor() {
     return setupUpdates_();
   }
   ```

   שמרו, בחרו `initializeUpdatesFromEditor` ולחצו **Run**. השלימו בעצמכם את אישור Google, אם נדרש, לאחר בדיקת ההרשאות.
6. בדקו ביומן שההכנה הסתיימה בהצלחה. **הסירו את כל הפונקציה הזמנית ושמרו לפני פריסה**: היא אינה מסתיימת ב־`_`, ולכן אין לכלול אותה בגרסה ציבורית.
7. בפריסה קיימת בחרו **Deploy → Manage deployments → Edit → New version → Deploy**. בפריסה ראשונה בחרו **New deployment → Web app**, הפעלה בתור **Me** וגישה **Anyone**. הגישה הציבורית היא לטופס בלבד; הגיליון נשאר פרטי. שמרו על כתובת `/exec` הקיימת בעדכון פריסה.
8. הכניסו את כתובת `/exec` ב־`webAppUrl` של `leads-config.js` באתר. זהו URL ציבורי; אין להוסיף לשם מזהה גיליון או הרשאות. כתובת `/dev`, כתובת העורך וכתובת ההפניה של `googleusercontent` אינן תחליף לכתובת הפריסה.
9. שמרו ופרסמו את עדכון האתר במסגרת תהליך הפרסום הרגיל ובהרשאה המתאימה. שינוי בקוד המקומי או בעורך Apps Script בלי עדכון הפריסה אינו מעדכן את הגרסה הציבורית.

### המרת המבנה הישן

`setupUpdates_` משתמש בלשונית הקיימת ואינו יוצר לשונית חלופית. הוא יכול להכין לשונית ריקה, לשמור רשימת נרשמים שכבר הוכנה, או להמיר את כותרות הפניות הישנות אם אין תחתיהן נתונים אמיתיים.

בהמרה מהמבנה הישן מותרת רק שורת הבדיקה הסינתטית המוכרת שנוצרה בהתקנה. הקוד בודק את המזהה, השם, מספר הבדיקה, יתר השדות והחתימה שלה לפני ההמרה. שורה אחרת, יותר משורת נתונים אחת, כותרות לא מוכרות, נתונים מחוץ לטבלה הישנה או מסנן שאינו תואם גורמים לעצירה. הקוד אינו הופך פניות קיימות להסכמה לדיוור. אם ההכנה נעצרה, יש לבדוק את הנתונים לפני שינוי ידני; אין למחוק שורות אמיתיות כדי לאלץ את ההמרה.

## כתובות הטופס וההטמעה

`doGet` מציג הרשמה לעדכונים כברירת מחדל. אפשר לציין את הכוונה במפורש:

- הרשמה מתוך העמוד: `/exec?mode=updates&source=updates`.
- הרשמה מבאנר היציאה: `/exec?mode=updates&source=exit`.
- להטמעה נוסף `&embed=1`; במצב הזה כותרת הטופס הפנימית מוסתרת, משום שהעמוד או הבאנר כבר מציגים כותרת.

אלה דוגמאות לסיומת של **כתובת הפריסה האמיתית**, לא כתובות עצמאיות. `leads.js` יוצר את הפרמטרים עבור הטופס בעמוד ועבור הבאנר.

קוד הפניות הישן נשמר לצורך תאימות, ונגיש רק כשמבקשים `mode=contact` במפורש. הוא אינו הטופס המוצג באתר הנוכחי. לאחר המרת הלשונית לרשימת תפוצה, בדיקת הכותרות מונעת ממנו לכתוב לתוכה פניות במבנה הישן.

ההטמעה משתמשת ב־`ALLOWALL`, ובאימות בין המסגרת לבין מקור האתר שהוגדר ב־`SITE_URL`. כתובת `localhost` או `127.0.0.1` אינה מקור האתר החי ולכן לא תקבל הרשאת הטמעה מהגדרה זו. בדיקה מקומית עם RPC מדומה אינה הוכחה לחיבור חי; יש לאמת את ההטמעה ממקור התואם ל־`SITE_URL`. שינוי הגדרה זו משפיע על הפרויקט, ולכן אין להחליפה בכתובת בדיקה בלי להחזיר את ההגדרה הנכונה לפני פרסום.

בהודעות `postMessage` עוברים אות טעינה, גובה המסגרת, nonce ואות הרשמה מוצלחת בלבד. פרטי הנרשם אינם נשלחים לעמוד המארח. קיימת אפשרות לפתיחה ישירה של הטופס אם ההטמעה אינה זמינה.

## התנהגות הבאנר

במחשב עם עכבר, הבאנר יכול להופיע כשהסמן יוצא מחלקו העליון של החלון, לאחר לפחות 25 שניות וצפייה ב־35% מהעמוד. ההצעה האוטומטית אינה נפתחת כשעורכים שדה או משתמשים בטופס, ומופיעה לכל היותר פעם אחת בביקור. אפשר לסגור אותה בלי להירשם ולפתוח שוב את ההרשמה ביוזמה מהכפתור; הרשמה מאושרת מסתירה הצעות נוספות באותו ביקור.

במסכי מגע אין זיהוי אוטומטי של ניסיון יציאה. ההרשמה זמינה בתוך העמוד ובפתיחה יזומה מהכפתור. אין לכידת כפתור החזרה, שינוי היסטוריית הדפדפן או אזהרת יציאה. הכפתורים משתמשים בכיתוב ברור ללא חיצים.

## בדיקת הפעלה אמיתית

- השתמשו במייל בדיקה שבשליטתכם. השם יכול להישאר ריק, והמייל והסכמה לקבלת עדכונים חייבים להיות מלאים.
- ודאו שהשליחה ננעלת בזמן הפעולה, ושהצלחה מופיעה רק לאחר אישור שמירה מהשרת.
- פתחו את הגיליון ובדקו שורה אחת עם שעה מקומית, מייל, מקור ההרשמה, סטטוס `רשום`, נוסח ההסכמה וגרסתה. לא צפוי להישלח מייל כחלק מההרשמה.
- נסו לשלוח שוב את אותו מייל, גם מתוך הבאנר: כתובת שכבר רשומה אינה אמורה ליצור שורה כפולה. ניסיון חוזר לאחר כשל רשת שומר את אותו מזהה בקשה כל עוד לא שונו הפרטים.
- בדקו בנפרד פתיחה ישירה, הטמעה באתר, הצגת שגיאת רשת וסגירת הבאנר במקלדת. הודעת הצלחה מקומית או בקשה שיצאה מהדפדפן אינן תחליף לאימות השורה בגיליון.
- אם נטפרי מציגה „האתר הזה עדיין לא נבדק”, יש לבקש בדיקה של כתובת הפריסה ולהמתין לפתיחתה. שינוי פרמטרים או מעבר לכתובת ההפניה אינם פתרון לעקיפת החסימה.

## ניהול הרשימה והסרה

בקשות הסרה מתקבלות במייל הציבורי `ysrael305@gmail.com`. לאחר בקשה יש לאתר את הכתובת ברשימה ולשנות את סטטוסה בעמודה E ל־`הוסר`. בעת חיבור מערכת דיוור או ייצוא עתידי יש לכלול **רק כתובות בסטטוס `רשום`**, בלי כפילויות, ולהחריג את כל שורות `הוסר`.

הרשמה חדשה עם הסכמה מפורשת לאחר הסרה יכולה ליצור שורת הסכמה חדשה; שורת ההסכמה הישנה נשמרת. אין לשנות סטטוס של נרשם שהוסר ל־`רשום` ללא הסכמה חדשה. יש לשמור את נוסח ההסכמה וגרסתה עם הרשומות, ולשנות גרסה בקוד אם משנים את הנוסח בעתיד.

## בדיקות וגבולות המערכת

משורש האתר: `npm run check` ו־`npm test`. בדיקות הדפדפן זמינות ב־`npm run test:browser` ודורשות Playwright בסביבת הפיתוח; אפשר להגדיר `PLAYWRIGHT_MODULE` להתקנה קיימת. בדיקות עם RPC מדומה בוחנות את הממשק ואינן מוכיחות כתיבה לחשבון Google. המסמך אינו מעיד שבוצעה בדיקת הרשמה חיה מקצה לקצה.

הקוד כולל אימות בצד השרת, הגבלות אורך, הגנה מ־Formula Injection, Honeypot, נעילה, זיהוי כפילויות והגבלת קצב בסיסית. Apps Script כפוף למכסות Google ואינו מספק כאן כתובת IP מהימנה למבקר; אין הבטחת זמינות או חסימת ספאם מוחלטת.

מקורות תיעוד: [תקשורת HtmlService עם השרת](https://developers.google.com/apps-script/guides/html/communication), [פריסת Web App](https://developers.google.com/apps-script/guides/web), [מכסות Google](https://developers.google.com/apps-script/guides/services/quotas), [נעילה ו־flush](https://developers.google.com/apps-script/reference/lock/lock).
